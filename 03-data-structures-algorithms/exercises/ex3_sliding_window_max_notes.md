# ex3 sliding_window_max 考点详解

## 题目回顾

`max_sliding_window(nums, k)`：用 `collections.deque` 维护**单调递减队列**，O(n) 求每个长度为 k 的窗口最大值。

期望：`[1,3,-1,-3,5,3,6,7]`，k=3 → `[3,3,5,5,6,7]`。

## 考点总览

| 考点 | 一句话 | 本题用法 |
| --- | --- | --- |
| `collections.deque` | 双端队列，两端 O(1) | 队尾进、队头出 |
| 单调队列 | 队列里值从队头到队尾递减 | 队头永远是当前窗口最大 |
| 存下标而非值 | 靠下标判断元素是否滑出窗口 | `nums[deq[0]]` |
| `popleft` / `pop` / `append` | deque 三件套 | 过期元素/被淘汰元素出队 |
| 时间复杂度 | 每个元素至多进出队一次 | O(n) |

## 1. 为什么是 deque 而不是 list

- `list` 的 `pop(0)`（从头部弹）是 O(n)；deque 的 `popleft()` 是 O(1)。
- C++ 对照：`std::deque`。本题完全可以用 `list` 实现但会退化成 O(n·k) 甚至更差。

```python
from collections import deque

d = deque([1, 2, 3])
d.append(4)        # 尾部进：1 2 3 4
d.popleft()        # 头部出：2 3 4
d.pop()            # 尾部出：2 3
print(d[0])        # 看队头不弹出
```

## 2. 单调队列思路

核心不变量：**deque 里存下标，按下标对应值从队头到队尾严格递减**。这样队头 `deq[0]` 永远是窗口最大值。

```python
def max_sliding_window(nums: List[int], k: int) -> List[int]:
    deq = deque()
    result = []

    for i, x in enumerate(nums):
        # 1. 新元素 x 入队前，把队尾所有 <= x 的干掉（它们不可能再当最大值）
        while deq and nums[deq[-1]] <= x:
            deq.pop()
        deq.append(i)

        # 2. 队头如果滑出窗口左边界，弹出
        if deq[0] <= i - k:
            deq.popleft()

        # 3. 窗口成形（i >= k-1）后，队头就是窗口最大值
        if i >= k - 1:
            result.append(nums[deq[0]])

    return result
```

逐步理解：

- **为什么要 `<=` 就弹**：新来的 `x` 比队尾大或相等，且下标更新，旧的永远不可能是后面窗口的最大值——“后来居上者全淘汰”。相等的也弹掉，留着没意义。
- **为什么存下标**：窗口滑动时，只有靠下标才能判断“`nums[i-k]` 是否已经滑出去”。
- **为什么过期判断在入队后**：入队的新下标 `i` 永远不过期（它刚进来）；只可能队头的老下标过期。

## 3. 复杂度

- 每个元素最多入队一次、出队一次，均摊 O(1)，总 O(n)。
- 朴素做法是每个窗口扫一遍 `max()`，O(n·k)。

## 4. 易错点清单

1. **deque 里存值不存下标**：窗口滑出时不知道哪个值过期了。
2. **过期判断写成 `deq[0] < i - k`**：窗口是左闭区间 `[i-k+1, i]`，滑出条件是 `<= i-k`。
3. **先 popleft 过期元素再淘汰队尾**：顺序反了可能导致队尾比较用错元素（其实不影响正确性，但按“先入队淘汰、再清理过期”写更顺）。
4. **`while deq and ...` 忘判空**：空队列访问 `deq[-1]` 直接 `IndexError`。
5. **结果里漏掉 `k-1` 之前的部分**：窗口不满 k 时没有最大值可输出。

## 5. 变式练习

- 求滑动窗口最小值：把“单调递减”改成“单调递增”。
- 求每个窗口的中位数（进阶：对顶堆 + 延迟删除）。
- 用 `heapq` + 懒删除实现同题，对比两种思路（堆有 O(n log k)，单调队列是 O(n)）。
